# 连接、重连与状态机规格

> 面向维护者。这是**两端共同规格**：桌面端是 Swift（[`RuntimeConnection.swift`][swift]），
> 移动端是 TypeScript（[`apps/mobile/src/client.ts`][mobile]）。两端不共享代码，只共享这份规格
> 和它对应的测试用例。

桌面端选 Swift 是为了嵌入 libghostty，这个选择不变；因此不存在「把连接层抽成共享包」的选项。
规格写在这里，两端各自实现、各自测试。

## 传输与握手

传输安全不依赖 TLS。所有连接走应用层 E2EE（X25519 + HKDF-SHA256 + ChaCha20-Poly1305，
见 [`e2ee.ts`][e2ee]），因此可以安全地经过 LAN 或 FRP 等明文公网代理。

一次连接的固定顺序：

1. WebSocket 升级。升级期可携带 admission 提示（token 哈希），仅用于连接配额，**不是**认证凭据。
2. 明文 `hello` 完成 X25519 握手。这是整条连接上唯一合法的明文消息。
3. 首条加密消息必须是 `auth`（带配对 token）。服务端校验 admission 提示与信道内 token 一致，
   再换出设备身份，回 `authed`（含本连接的 scopes）。
4. 之后所有文本帧是 RPC，二进制帧是终端 / 画面数据。

握手违规、解密失败、认证失败一律直接断开连接，不返回错误响应。

一个远程 Runtime 对客户端 = 一个 token + 多个入口（LAN、公网代理）。从任何入口连上都是同一设备身份、
同一批会话；服务端不区分连接来源。

## 状态机规格

以下是两端都必须满足的行为。**桌面端已实现**的项标注了对应实现；标注「待实现」的是移动端做起来时
必须补齐的部分，也是当前两端的差距。

### 重连与退避

| 规格 | 桌面端 | 移动端 |
|---|---|---|
| 退避阶梯，尾项为稳态重试间隔 | `reconnectDelays = [0.5, 1, 2, 3, 5, 8]` 秒 | 待实现 |
| 失败后轮换入口（LAN 不通换公网） | `endpointIndex += 1` after disconnect | 待实现 |
| 显式重连立即打断退避 | `connect(server:)` 重置 `reconnectAttempt` | 待实现 |
| **连接稳定一段时间后重置退避阶梯** | 待实现 | 待实现 |
| **离线时释放会话并等待信号，不消耗重试次数、不跑定时器** | 待实现 | 待实现 |
| **认证或配置错误保持阻塞，直到相关输入改变** | 待实现（当前一律重试） | 待实现 |

前两项已经在跑；后三项是 t3code 连接规格里 Acro 尚未覆盖的部分。它们的共同动机是：
**退避次数是为「服务端暂时不可达」准备的，不该被「本机没网」或「token 已失效」消耗掉。**

### 探活

- 已连接时按固定间隔发 ping（桌面端 `startProbe`，15 秒）。上一发 ping 未在整个间隔内得到 pong，
  判定为半开连接，主动断开并走重连。取自 orca 的 ws-transport。
- 服务端侧有对称的心跳回收（[`ws.ts`][ws] 的 `alive` 标志）。

### 应用生命周期唤醒（移动端为主，桌面端同样适用）

这一组是移动端最容易做错的地方，逐条写死：

- **建连过程中收到普通的「应用回到前台」→ 忽略。** 重启一个在途的连接尝试只会让它更慢。
- **从长时间后台恢复 → 打断建连并重置退避阶梯。** 系统可能已经悄悄杀掉了 socket，
  在途的尝试是在等一个永远不会来的响应。
- **已连接时回到前台 → 发探针，不要重连。** 健康的会话应该活过前台切换。
- **显式断开、显式重连、进入离线 → 任何阶段都立即打断。**
- 退避等待期间回到前台 → 重置阶梯并立即重试，不要服完剩余延迟。

### 连接状态与数据同步状态是两个维度

不要用「有没有缓存数据」或「transport 对象存不存在」推断连接健康。

- 连接状态：`disconnected` / `connecting` / `connected`。
  `connected` 的判据是 socket 打开**且**初始配置 RPC 成功——证明服务端真的在响应。
- 数据同步状态：按域独立（会话、工作区、布局各自有自己的同步状态与错误）。

RPC 传输正常但某个订阅失败，应显示为「已连接 + 同步错误」，而不是「正在重连」——
因为此刻并没有安排任何重连。

### 失败分流

- **传输层失败**：结束当前订阅，等待新连接接管。不要在同一条已死的连接上重试。
- **业务层失败**：在**同一条**连接上处理（必要时延迟重订阅）。健康的传输不因业务错误被拆掉。

## 断点续传

- 事件带 `seq` 和 `boot`。`boot` 变了说明服务端重启过，客户端必须全量重新同步；
  `seq` 用于同一 boot 内补齐。
- 终端 attach 先收快照（含 scrollback）再收增量，`session.attach` 返回快照覆盖到的 `seq`，
  之后的 `FRAME_OUT` 从 `seq + 1` 开始。快照与增量必须同轮对齐（取自 orca）。
- 客户端布局可以不同，但引用相同的服务端 Session。

## 多客户端

- 终端占用：某设备 focus 即认领，其他设备须显式 `force` 接管。非占用设备的输入被网关丢弃。
- 输入 owner 同时决定 PTY 尺寸；观察端 resize 不得干扰操作端。
- 桌面端是多主机的：为每台已配对 Runtime 维持一条常驻连接（RuntimeHub），
  侧边栏按服务器分组显示各自的工作区。

## 验证

两端都应覆盖：离线启动后上线、退避封顶与重置、显式重连打断退避、认证失败后的唤醒、
非自愿断开后重连、显式移除清空该环境的全部本地状态、快照与增量的 seq 对齐。
